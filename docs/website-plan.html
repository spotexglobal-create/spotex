Masle jo nayi site mein theek karne hain

  • SEO: sitemap.xml maujood hi nahi (404). Homepage ki meta description abhi tak template wali "Your site description is here" hai. Title sirf "Spotex International".
  • Filler text: homepage pe "It is a long established fact…" aur "It has survived not only five centuries" jaise dummy lines. Buyer ko yeh foran ghair-professional lagta hai.
  • Kisi aur site ka menu: HTML mein ek purane template ka chhupa menu hai ("History of WCCIS", "STSI Executive Committee", "History of Sialkot").
  • Facts aapas mein takrate hain: ek jagah "1989 se", ek jagah "29 saal", homepage pe "15+ years". Homepage yeh bhi kehta hai ke company "partners with top manufacturers", jab ke asal taqat yeh hai ke sab kuch apni factory mein banta hai.
  • Spelling: "SAMBA UNIFORM" (Sambo hona chahiye), "MMa Shorts", "Key Chain's", "Leggies".
  • Phone number: header mein …33 34 aur contact page pe …33 33.
  • Product codes: do system chal rahe hain (SI-JJU-1001 aur JJ-102-(STI-3)).
  • Language: sirf English, koi hreflang nahi.

03Naya domain

  • Naam: chhota, aasaan spelling, aur "Spotex" naam ke saath, taake brand wahi rahe. .com sab se behtar hai, kyun ke teeno markets ke liye ek hi domain hoga aur language subfolder se badlegi.
  • Ek domain, language folders: newdomain.com/en, /no, /de wagaira. Har mulk ka alag domain (.no, .de) mat lein. Is se SEO ki taqat bat jati hai aur kharcha bhi barhta hai.
  • Email: naye domain pe professional email (Google Workspace ya Zoho), jaise sales@, info@. SPF, DKIM aur DMARC set karein, warna Europe mein emails spam mein jayengi.
Faisla: sirf naya domain use hoga. Purana spotexint.com is project mein shamil nahi, aur us se koi redirect nahi hoga. Is liye naya domain SEO mein zero se shuru karega. Isay jaldi mazboot karne ke liye launch ke din Alibaba profile, Google Business Profile, LinkedIn, Facebook, Instagram aur B2B directories pe naye domain ka link lagayein, aur Search Console mein sitemap submit karein. Domain kam se kam 2 saal ke liye renew rakhein.

04Languages aur regions

Abhi 4 languages: English, German, Norwegian aur Italian. Visitor jis mulk se aaye, use us mulk ki zubaan mein site dikhe. Baaki saari duniya ko English. Baad mein nayi language add karni ho to sirf ek JSON file aur admin mein ek tab barhega.

Kaise kaam karega

  1. Visitor newdomain.com kholta hai. Next.js middleware hosting ka country header (x-vercel-ip-country ya cf-ipcountry) aur browser ki language parhta hai.
  2. Upar wali table se language chun kar sirf homepage pe redirect, aur choice cookie mein save.
  3. Header mein har waqt language switcher. User ki apni choice hamesha IP pe bhari rahe.
  4. Andar ke pages (jaise /de/judoanzug) kabhi zabardasti redirect nahi honge. Google zyada tar USA se crawl karta hai, aur force redirect se use German aur Norwegian pages kabhi nahi milenge.
  5. Har page pe hreflang tags aur x-default (English), taake Google khud har mulk ko sahi page dikhaye.
Translation: UI ka text (buttons, menu) next-intl ki JSON files mein, aur products, blog aur SEO fields MongoDB mein har language ke liye alag. Main pages ki translation us zubaan ke native translator se karwayein. Machine translation se B2B buyer ka bharosa toot jata hai. URL slugs bhi translate hon: /de/judoanzuege, /no/judodrakter, /it/judogi.

Content

  • Products: add, edit, delete, duplicate. Har language ka apna tab
  • Categories aur sub-categories

Folder structure

spotex/                   ek hi Next.js project, Vercel pe
├─ app/
│  ├─ [locale]/             website pages (en, de, no, it)
│  ├─ admin/                admin portal
│  └─ api/                  API routes: products, categories, inquiries, auth, uploads …
├─ lib/
│  ├─ db.ts                 MongoDB connection (cached, har request pe naya nahi)
│  ├─ models/               Mongoose models
│  ├─ auth.ts               login, session, role check
│  └─ validation/           Zod schemas
├─ messages/                en.json, de.json, no.json, it.json
├─ components/
└─ middleware.ts            country → language, aur /admin ki hifazat
Vercel pe 3 baatein: (1) MongoDB connection lib/db.ts mein cache ho, warna har request pe naya connection banega. (2) Logo aur images browser se seedha Cloudinary pe upload hon (signed upload); API sirf signature deti hai, kyun ke Vercel pe request size ki limit hai. (3) Lamba kaam Vercel Cron se chale.
Speed: admin mein product save ho to API usi waqt revalidatePath chalaye, aur sirf woh page dobara bane. Is tarah site static jaisi tez rahegi aur update bhi foran dikhega. Heavy animation sirf homepage pe rakhein, aur "reduced motion" wale users ke liye band kar dein.
